# METRICS — каталог метрик CDXMonitor

Источник по умолчанию: `rollout-*.jsonl` (см. `docs/AUDIT.md`, раздел 3).
Легенда категорий: Д — достоверная (прямо из источника), В — вычисляемая (точная формула от Д),
О — оценочная (с допущениями, маркируется в UI), Н — недоступная (нет безопасного источника).

## 1. Контекст (scope: одна сессия/rollout)

| Метрика | Кат. | Источник / способ | Ед. | Обновление |
|---|---|---|---|---|
| Активная модель | Д | `turn_context.model`, fallback `session_meta`/`world_state`/`thread_settings_applied` | строка | по событию |
| Reasoning effort | Д | те же записи | строка | по событию |
| ID сессии/треда | Д | `session_meta.id`/`session_id`, `turn_context.turn_id`/`root_turn_id` | строка | при старте |
| Проект (cwd) | Д | `session_meta.cwd` / `turn_context.cwd` | путь | при старте |
| Максимальное окно контекста | Д | `token_count.info.model_context_window` (вживую 258400); справочно каталог `models_cache.json` (272000 × 95%) | токены | по событию |
| Занято контекста (TURN input) | Д | `token_usage_record.usage.input_tokens`, fallback `last_token_usage.input_tokens` | токены | по usage-событию |
| Заполнение контекста | В | `last_input / window × 100` | % | по событию |
| Остаток контекста | В | `window − last_input` | токены | по событию |
| Fresh-токены | В | `input − cached` | токены | по событию |
| Cache ratio | В | `cached / input × 100` | % | по событию |
| Δ контекста за событие | В | `last_input − prev_input` (может быть отрицательной после compaction) | токены | по событию |
| История заполнения | В | ряд `last_input` по меткам `timestamp` | токены/время | по событию |
| Число compaction | Д* | топ-записи `compacted` (`window_number`, `window_id`-цепочка); *требует нового парсера, в исходнике отсутствует | шт. | по событию |
| Время последнего compaction | Д* | `compacted.timestamp`; то же условие | время | по событию |
| Контекст после сжатия | Д* | `compacted.latest_token_usage_record.usage` + `thread_token_usage`/`turn_token_usage` | токены | по событию |
| Совокупный расход сессии (ROLLOUT) | Д/В | сумма `token_usage_record` + max-согласование с `total_token_usage` (без двойного счета) | токены | по событию |

Не путать: текущий контекст (TURN input) vs суммарный расход сессии (ROLLOUT).

## 2. Токены

| Метрика | Кат. | Источник / способ | Ед. | Обновление |
|---|---|---|---|---|
| Input / Cached / Output / Reasoning / Total за TURN | Д | `usage` последнего события | токены | по событию |
| Cache-write токены | Д | `usage.cache_write_input_tokens` (исходник игнорирует) | токены | по событию |
| TASK-расход (с `turn_id`) | Д/В | накопление от базлайна `total − last` (см. AUDIT §2) | токены | по событию |
| ROLLOUT-расход | Д/В | как выше | токены | по событию |
| Расход за последний запрос | Д | TURN после каждого usage-события (событие ≈ модельный вызов; не называть «API-запросом») | токены | по событию |
| День / неделя / весь период | В | агрегация событий по `timestamp` (история CDXMonitor) | токены | 1–5 c |
| По моделям / проектам | В | группировка по `model` / `cwd` при мультисессионном скане | токены | 5–30 c |
| Скорость генерации | О | `output / Δt` между соседними событиями; Δt — стенное время, не длительность вызова | tok/s | по событию |
| Счетчики задач (started/done/running) | Д | `task_started`/`task_complete`/`turn_aborted` по `turn_id` | шт. | по событию |

Накопители переживают рестарт монитора (реплей файла + `total − last`); повторное чтение не дублирует счет (идемпотентный max-реплей).

## 3. Лимиты и сбросы

| Метрика | Кат. | Источник / способ | Ед. | Обновление |
|---|---|---|---|---|
| Primary-лимит (5h): расход | Д | `rate_limits.primary.used_percent` | % | по `token_count` |
| Primary: сброс | Д/В | `primary.resets_at` → обратный отсчет | время | 1 c (тик UI) |
| Secondary-лимит (weekly): расход | Д | `rate_limits.secondary.*` (исходник не показывает) | % | по `token_count` |
| Secondary: сброс | Д/В | `secondary.resets_at` → обратный отсчет | время | 1 c |
| Имя/ID лимита, credits, флаги | Д | `limit_name`, `limit_id`, `credits{...}`, `spend_control_reached`, `rate_limit_reached_type` | смеш. | по событию |
| Тип плана | О/Н | `plan_type` ненадежен (пропадает в свежих файлах) — показывать только при наличии, с маркером | строка | — |
| История сбросов | О/Н | явных маркеров сброса в схеме нет; падение `used_percent` — косвенный признак, не факт | — | — |
| Ручной сброс / новый тред vs compaction | Н | различить нечем: маркеров нет. Не выдумывать | — | — |

Не смешивать: обновление 5h-лимита, обновление weekly-лимита, ручной сброс, compaction, новая сессия.

## 4. Сессии и история

| Метрика | Кат. | Источник / способ |
|---|---|---|
| Список сессий (primary + auxiliary с меткой) | Д | скан `sessions/`, классификатор, `session_index.jsonl`, `threads.rollout_path` |
| Название, модель, cwd, создан/обновлен, архивность | Д | `state_5.sqlite.threads` (недокументирован — изолированный адаптер) |
| Статусы и длительности turns | Д | `thread_history.thread_turns` (`status`, `duration_ms`) |
| Per-сессия и суммарная статистика | В | агрегация парсером по каждому rollout |
| История за период, группировки | В | SQLite CDXMonitor (собственная история наблюдений) |
| Статистика аккаунта | Н | локальные файлы ≠ аккаунт; только нижняя оценка с маркером О |

## 5. Дополнительные (предлагаемые) метрики

| Метрика | Кат. | Источник |
|---|---|---|
| Ошибки turns / уровни логов | Д | `thread_turns.status`+`error_json` (ключи), `logs_2.logs.level/target` (агрегаты, без тел) |
| Активность инструментов | Д | подсчет `response_item` типов (`function_call`, `custom_tool_call`) — счетчики, без аргументов |
| Здоровье источников (файл найден/растет/ошибка парсинга, счетчик неизвестных записей) | В | самодиагностика коллектора |
| Версия Codex (`cli_version`), originator | Д | `session_meta` |
| Окно каталога vs эффективное (272000 / 95% / 258400 / max 872000) | Д | `models_cache.json` |
| Прогноз заполнения окна (линейная экстраполяция) | О | ряд TURN; маркировать как прогноз |

## 6. Запрещено к сбору

Полный текст диалогов (`replacement_history`, `message.content`, `item_json` тел), секреты (`auth.json`, `.sandbox-secrets`, `secrets/`), содержимое `mcp-oauth-locks`. Парсер читает только структурные/числовые поля из белого списка.
