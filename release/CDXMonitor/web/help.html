CDXMonitor — установка, запуск, работа

Локальный монитор статистики Codex Desktop. Только чтение данных, без сети и патчей Codex.

1. Требования

  • Windows 11 x64, установленный Codex Desktop (источник данных: %USERPROFILE%\.codex\sessions).
  • Node.js 24+ в PATH (для текущей dev-сборки; переносимая сборка решит вопрос рантайма на этапе E8).

2. Первый запуск (dev-сборка)

cd CDXMonitor
npm install
npm test        # сборка + проверки
npm run build:ui
npm run serve   # сервер на http://127.0.0.1:8765/

Откройте http://127.0.0.1:8765/ во встроенном браузере правой панели Codex Desktop.

Если порт 8765 занят — сервер честно сообщит об этом и завершится. Освободите порт или запустите с другим: npm run serve -- --port 8766.

3. Старт без сервера (boot-страница)

Файл web\boot.html открывается двойным кликом без запущенного сервера: показывает статус и кнопку запуска. Кнопка использует протокол cdxmonitor://start — его регистрирует install.ps1 при установке (HKCU, без прав администратора).

Если кнопка не срабатывает: протокол не зарегистрирован — запустите install.ps1 один раз либо start.cmd вручную. Без протокола страница тоже работает: поднимите сервер вручную, она сама перейдет на монитор.

4. Вкладки интерфейса

ВкладкаСодержимое
OverviewМодель, контекст (занято/окно/%), TURN/TASK/ROLLOUT кратко, лимиты, задачи, compaction
ContextОкно, остаток, fresh, cache ratio, дельта за событие
TokensПолная таблица input/cached/cache-write/fresh/output/reasoning/total по TURN/TASK/ROLLOUT
LimitsЛимиты 5h и weekly: расход, обратный отсчет сброса, атрибуты лимита

Данные обновляются автоматически каждую секунду (SSE), перезагрузка не нужна.

5. Как читать показатели

  • TURN — последнее событие использования; TASK — расход с начала текущей задачи; ROLLOUT — суммарно по файлу сессии. Текущий контекст и суммарный расход — разные вещи.
  • Fresh = input − cached. Reasoning-токены могут входить в output и показываются отдельно.
  • Primary (5h) и secondary (weekly) — разные лимиты с разными сбросами, не смешивайте их. Время сброса — обратный отсчет от метки Codex.
  • Метка N/A — данных нет (не ноль). Метка EST — оценка, а не факт.
  • Монитор следит за новейшим основным тредом; служебные review-ответвления пропускаются.

6. Решение проблем

СимптомДействие
Статус WAIT / «Нет связи с сервером»Проверьте, что сервер запущен и адрес введен точно
Порт занятОстановите второй экземпляр или задайте --port
Пусто после переустановки CodexСессии лежат в .codex\sessions — дождитесь новой активности Codex
Подозрительные цифры после обновления CodexСмотрите вкладку Diagnostics (этапы E4–E7): счетчик неизвестных записей схемы

7. Приватность

Монитор читает только числовые и структурные поля статистики. Тексты диалогов, файлы авторизации и секреты не читаются, не логируются и не показываются. В .codex ничего не пишется.

8. Переносимая сборка: какие файлы, куда, как запустить

Пакет release/CDXMonitor/ собирается из исходников скриптом scripts\build-release.ps1. Переносится целиком, как есть.

Файл/папка пакетаНазначение
web/Интерфейс: монитор, boot.html, help.html (эта страница), pages/
server/Локальный сервер и сборщик статистики (готовый к запуску)
config/cdxmonitor.jsonНастройки: порт (8765), bind, каталог сессий, dataDir
data/Ваши данные (история, PID-файл). При обновлении не затирается
start.cmdЗапуск двойным кликом
stop.cmdОстановка
install.ps1Установка с выбором расположения и сохранением data/
uninstall.ps1Удаление только файлов CDXMonitor (data/ сохраняется)
README.mdКраткая инструкция пакета

Куда переносить (окончательное расположение утверждается отдельно):

  • %LOCALAPPDATA%\OpenAI\Codex\CDXMonitor — рядом с Codex (основной вариант);
  • %LOCALAPPDATA%\CDXMonitor — запасной вариант.

Как перенести: скопируйте содержимое release/CDXMonitor/ в целевой каталог вручную либо запустите install.ps1 — он спросит расположение, проверит права и сохранит существующую папку data/. Файлы самого Codex (bin, runtimes и др.) не затрагиваются.

Как запустить:

  1. Двойной клик start.cmd в папке установки.
  2. Во встроенном браузере правой панели Codex откройте http://127.0.0.1:8765/ (порт — из config/cdxmonitor.json).
  3. Остановка — двойной клик stop.cmd.

Удобнее: действие Start CDXMonitor через Local Environments → Actions в настройках Codex (действие запускает start.cmd во встроенном терминале; без изменения файлов Codex). Требуется Node.js 24+ в PATH. Вкладка с локальным адресом может не восстанавливаться после перезапуска Codex — тогда откройте адрес заново.
